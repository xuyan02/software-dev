# 流程编辑器交互设计

> 状态：评审稿 · 2026-11-06
> 范围：`web/workflow-editor` 的草稿页、只读页、历史版本页
> 关联：[编辑器操作说明](../operations/workflow-editor.md)、[Workflow AST](../domain/workflow-ast.md)、[RFC 0005](../rfcs/0005-workflow-definitions.md)、[RFC 0006](../rfcs/0006-workflow-variables.md)、[RFC 0007](../rfcs/0007-workflow-script-syntax.md)

本文定义交互行为、反馈、状态和文案，不修改 AST、校验规则或 API。凡是与当前实现不同的地方，都在第 21 节“与当前实现的差距”中列出。标有 **RFC 缺口** 的内容是 RFC 已经要求、当前编辑器尚未实现的交互，它们是本文的目标，不是现状。

## 1. 一句话模型

画布负责“看见结构”，并且只承载两种有空间含义的操作：**移动 stage 的位置**、**从 stage 拉出转移**。其余修改都在右侧检查器完成。保存自动进行；移动 stage 只改布局，不产生版本；发布生成不可变的版本。

## 2. 目标

用户在任何时刻都能回答四个问题：

1. 我在草稿还是只读版本？
2. 我刚才改的是流程定义，还是只是布局？
3. 修改保存到哪一步了？
4. 为什么现在不能发布？

具体目标：

- 每个可编辑对象都有可见的创建、编辑、删除入口；没有隐藏手势。
- 危险操作要么可撤销，要么明确确认；草稿允许暂时不完整，但错误必须能定位。
- 指针、键盘、触控都能完成核心工作；拖拽有键盘替代。
- 不引入 AST 之外的新概念。模板、布局、选中状态都只是编辑器的投影或本地状态。

## 3. 非目标

- 不修改 AST、校验规则、发布语义；不新增字段、表或 API 操作。
- 不做多人实时协同、锁或自动合并；冲突只提供“载入服务端”和“覆盖”两种选择。
- 不做多选、框选、成组拖动。理由见第 20 节。
- 不做移动端优先布局；窄屏只保证可用。
- 不做脚本 IDE 之外的通用代码编辑器；脚本能力的上限由 RFC 0007 定义。
- 不做画布上的自由批注、便签或分组容器。
- 不增加“+ 转移”按钮。鼠标和触控下，转移只能通过拉线创建。

## 4. 设计原则

1. **单一真相。** AST 是流程定义的唯一真相；画布、stage 图形、边、检查器、版本 diff 都是它的投影。布局和视口是另外两层状态，不能和 AST 混为一谈。
2. **直接操作只用于有空间含义的动作。** 移动位置、拉出转移适合直接操作；改脚本、改角色、改变量适合表单。不要为了“图形化”把表单操作硬做成拖拽。
3. **一个对象一个主入口。** 每个对象只有一条主要创建路径和一个主要编辑位置。可以有快捷方式，但不出现两个互相竞争、语义相同的按钮。
4. **可逆优先于确认。** 能用撤销解决的就不要弹确认；不可逆、会丢弃他人内容或会破坏大量结构的操作才确认。
5. **结构错误要预防，语义错误要暴露。** 非法的 name、重复的 event、空的 operation roles 这类结构问题在输入时拦住；脚本引用、不可达 stage、死胡同这类语义问题交给校验面板。
6. **只读不是禁用。** 只读页面用文档式呈现，而不是满屏灰色控件。禁用控件既占空间，又让人以为“再点一下就能编辑”。
7. **状态必须可见。** 模式、保存状态、布局状态、校验新鲜度、发布阻塞原因都要在界面上有位置，不能只放在 `title` 提示里。
8. **指针选择不抢焦点，键盘激活才移动焦点。** 鼠标点选只改变选中对象；用键盘确认时才把焦点送进检查器。
9. **反馈分级。** 瞬时结果放状态栏；需要用户决策的放横幅；破坏性操作放确认对话框；不要引入独立的 toast 系统。
10. **不发明领域。** 不新增 stage 的 display_name、不新增 terminal 状态、不新增“+ 转移”入口；`ended` 始终是虚拟完成目标，不是 stage。

## 5. 术语和文案基线

| 术语 | 用法 | 不要用 |
|---|---|---|
| 流程 | workflow 的面向用户称呼 | 过程、工作流（正文统一“流程”） |
| stage | 保留英文，小写 | 阶段（解释时可用，界面用 stage） |
| 转移 | transition | 迁移、流转 |
| 进入效果 | `created` 列表 | 进入动作、初始化动作 |
| 任务变量 | workflow 顶层 `vars` | 全局变量 |
| stage 变量 | stage 的 `vars` | 局部变量、临时变量 |
| 角色 | `roles` 中的声明 | 岗位、参与者类型 |
| 校验 | validation 的结果 | 验证、检查（“检查”可作动词） |
| 草稿 | 当前共享工作副本 | 工作区、未发布版本 |
| 版本 | 已发布且不可变的快照 | 发布记录 |
| 布局 | stage 的展示位置 | 排版、坐标数据 |

界面文案规则：

- `on`、`action`、`to`、`set_state`、`event` 等 AST 字段名保留代码格式；解释性文字用中文。
- stage 和角色只有 `name`，没有显示名。变量和 operation 有 `display_name`；在列表、选择器和只读视图里优先显示 `display_name`，机器名作为次要信息。
- 角色类型显示为“人类 / 智能体 / 不限”，不直接显示 `human / agent / any`；需要时在括号里附原值。
- 任务状态显示为 `pending（待处理）`、`in_progress（进行中）`；`completed` 不出现在 `set_state` 选项里。
- `ended` 显示为“结束（ended）”，并明确“不是 stage，不能作为初始 stage”。

## 6. 界面结构

```text
┌────────────────────────────────────────────────────────────────────┐
│ 工具栏：返回 · 标题/所有者 · 模式 · 保存状态 · 版本 · 编辑/布局/发布 │
├────────────────────────────────────────────────────────────────────┤
│ 横幅区：冲突 · 本地备份恢复 · 消息（按需出现）                       │
├──────────────────────────────────────────┬─────────────────────────┤
│ 画布                                     │ 侧栏                    │
│  Start ── stage 图形 ── stage 图形 ── End│ 检查器（当前选中对象）  │
│                                          │ 任务变量                │
│                                          │ 角色                    │
│                                          │ 校验                    │
├──────────────────────────────────────────┴─────────────────────────┤
│ 状态栏：保存/布局状态 · 快捷键提示 · 校验摘要 · 数量统计            │
└────────────────────────────────────────────────────────────────────┘
```

### 6.1 工具栏

从左到右分为四组，用分隔线区分：

1. **导航**：`← 流程`、标题、所有者。
2. **状态**：模式徽标（`草稿` 或 `只读 · vN`）、保存徽标、版本选择器。
3. **编辑**：撤销、重做。新增 stage/operation/子任务的入口在右侧栏顶部的对象工具栏（见 11.10）。
4. **布局与发布**：`自动布局`、`保存`、`发布`。

规则：

- 模式徽标必须始终可见，不能只靠版本选择器推断。
- 保存徽标表达的是 **AST 草稿** 的保存状态；布局状态在状态栏单独显示。
- 版本选择器是导航控件，不是编辑控件。选择历史版本前先 flush 草稿；flush 失败时先询问，不静默离开。
- 撤销/重做在历史为空时禁用，`title` 显示下一项动作名，例如“撤销：重命名 stage review”。
- `保存` 在没有未保存修改时禁用；`发布` 禁用时必须把原因显示在按钮旁边，而不是只放在 `title` 里。
- 只读模式隐藏撤销、重做、`保存`、`发布` 和 `自动布局`，只保留导航、版本和查看操作；对象工具栏也不显示。

### 6.2 横幅区

横幅按优先级从上到下排列：

1. **冲突**：红色，常驻，直到解决。
2. **本地备份恢复**：黄色，常驻，直到恢复或丢弃。
3. **消息**：成功为绿色，错误为红色；成功消息 6 秒后自动消失，错误消息保留到用户关闭或下一次操作覆盖。

横幅内的按钮必须写清楚后果，例如“载入服务端版本（丢弃本地修改）”。破坏性按钮用 danger 样式，并在执行前弹出确认。

### 6.3 画布

画布包含：

- Start 和 End 两个标记，不是可编辑 stage；可编辑草稿中可以自由拖动，只改布局。
- 每个 stage 一个图形；图形内只显示 name 和初始标记，不显示事件、进入效果、转移或其他内部信息。这些对象在右侧检查器里查看和编辑。
- 边来自 transition；`to = ended` 的边指向 End。
- 左下角缩放控件（放大、缩小、适应画布），不显示交互式小地图。
- 可编辑草稿中，空画布显示引导；只读视图中，空定义显示明确的“暂无内容”状态。

### 6.4 侧栏

侧栏从上到下：

1. **检查器**：当前选中对象的编辑器；没有选中时显示 stage 导航列表和操作提示。
2. **任务变量**：跨 stage 保留的变量。
3. **角色**：全流程角色列表和新增表单。
4. **校验**：错误和警告。

规则：

- 选中任何对象时，检查器顶部显示面包屑：`所有 stage / review / 操作 approve`。点击“所有 stage”回到导航列表；点击 stage 名回到 stage 编辑器。
- 检查器切换对象时滚动到顶部；从校验或 diff 定位时滚动到具体字段并短暂高亮。
- 校验错误存在时，工具栏的发布按钮旁显示错误数量；点击数量滚动到校验面板，不自动展开或重排侧栏。

### 6.5 状态栏

状态栏始终显示：

- 保存状态（与工具栏徽标一致）。
- 布局状态：`布局已保存 14:32`、`布局保存中…`、`布局未保存 · 重试`。
- 快捷键提示：`Ctrl/Cmd+S 保存 · Ctrl/Cmd+Z 撤销`。
- 校验摘要：`2 个错误`、`1 个警告` 或 `通过`。
- 数量统计：`N 个 stage · M 个角色`。

只读模式下隐藏快捷键提示，显示“只读，拖动空白处平移画布”。

## 7. 三种状态层：先回答“拖动到底改了什么”

这是最容易让人误判的地方，必须在界面上讲清楚。

| 层 | 内容 | 保存方式 | 进入版本 | 可撤销 | 只读可见 |
|---|---|---|---|---|---|
| AST | stage、operation、event、进入效果、转移、角色、变量 | 草稿自动保存，带 revision | 发布时 | 是 | 是 |
| 布局 | 每个 stage 的 `{x, y}` | 独立的布局接口，last-write-wins | 否 | 是（本地） | 是（共享） |
| 视口 | 平移和缩放 | 不保存 | 否 | 否 | 是（本地） |

由此得到四条硬规则：

1. **拖动 stage 只改布局。** 不推进 revision，不改变保存徽标，不产生版本。
2. **布局保存失败不影响 AST。** 状态栏提示，不弹错误横幅，不阻止继续编辑。
3. **只读视图不能改布局。** 历史版本页和非所有者看到的图使用共享布局；它们不能拖动 stage 或 Start/End 标记。
4. **发布只快照 AST。** 版本页使用当前共享布局，因此同一版本在不同时间打开，位置可能不同；这是有意的，布局不是定义。

### 7.1 四种拖拽结果

| 手势 | 可编辑草稿 | 只读 |
|---|---|---|
| 拖 stage 图形 | 只移动该 stage，保存布局 | 不响应；图形不可拖动 |
| 拖 Start / End 标记 | 只移动该标记，保存布局 | 不响应；标记不可拖动 |
| 拖空白画布 | 平移画布 | 平移画布 |
| 中键拖动 / 按住空格拖动 | 平移画布 | 平移画布 |
| 从 stage 右侧手柄拖出 | 创建转移 | 没有手柄 |
| 从对象工具栏把「阶段」拖到空白画布 | 在落点新建 stage | 没有对象工具栏 |
| 从对象工具栏把「操作」拖到 stage 或 operation 标签 | 在该 stage 新建 operation | 没有对象工具栏 |
| 从对象工具栏把「子任务」拖到 stage | 在该 stage 新建 `create_child` 进入效果 | 没有对象工具栏 |
| 滚轮 | 缩放 | 缩放 |

**为什么只读图形不响应拖动。** 让“拖图形”变成“平移画布”会造成强烈的错误因果：用户以为在移动图形，实际移动了世界。只读时 stage 图形保持完全静止，光标为默认箭头；需要平移时拖空白、按住中键或按住空格。这样“拖图形没反应”和“拖画布会平移”是两件清楚分开的事。

### 7.2 如何一眼判断当前页

| 信号 | 可编辑草稿 | 只读 |
|---|---|---|
| 顶部徽标 | `草稿` | `只读 · vN`；没有已发布版本时 `只读 · 未发布` |
| 检查器新增入口 | `+ 事件`、`+ set_state` 等 | 没有 |
| 对象工具栏 | 有「阶段」「操作」「子任务」 | 没有 |
| stage 图形左右手柄 | 有 | 没有 |
| stage 图形光标 | `grab` | 默认箭头 |
| 检查器 | 表单 | 文档式只读 |
| 拖 stage 图形 | 图形移动 | 图形不动 |

这些信号必须一致。如果徽标说“草稿”、对象工具栏可见、图形手柄可见、光标是 `grab`，那么拖图形却不移动，就是缺陷；如果其中任何一个说“只读”，拖图形不动就是正确行为。

## 8. 模式与权限

### 8.1 可编辑草稿

- 谁：账户流程的所有者；平台流程的平台管理员；人类账户。
- 数据源：草稿接口。
- 界面：`草稿` 徽标、保存状态、撤销/重做、全部编辑入口。
- 布局可编辑并保存。

### 8.2 只读

- 谁：Agent 账户（包括 PM agent）；非所有者的账户成员；非平台管理员的平台流程查看者；历史版本页。
- 数据源：可编辑者看到草稿；不可编辑者看到最新已发布版本。草稿对不可编辑者不可见。
- 界面：`只读 · vN` 徽标；没有编辑控件；检查器用文档式呈现；没有对象工具栏和连接手柄；stage 图形不可拖动。
- 只读用户可以选中 stage、operation 标签、边和角色来查看详情，也可以从检查器的 stage 列表进入事件、进入效果和转移，可以复制文本。
- 平台流程的只读用户可以复制到自己的账户（入口在版本页）。
- 没有已发布版本且不可编辑时，不显示空画布，显示“该流程尚未发布，暂无可查看内容”。

### 8.3 历史版本页

- 路径：`/workflows/editor/{id}/versions/{n}`。
- 始终只读；显示 `只读 · v{n}`、发布者、发布时间。
- 版本选择器切换版本；对比选择器选择另一个版本。
- 可编辑者有“返回草稿”；平台流程有“复制到我的账户”。
- 侧栏必须包含任务变量、角色和检查器；不显示运行期变量值，只显示定义。

### 8.4 权限矩阵

| 查看者 | 平台流程 | 账户流程（自己的） | 账户流程（别人的） |
|---|---|---|---|
| 平台管理员 | 编辑/发布 | 只读 | 只读 |
| 人类账户 | 只读 | 编辑/发布 | 不可见 |
| Agent 账户 | 只读 | 只读 | 不可见 |

只读不是“字段级禁用”。权限决定整个页面的模式；页面内不再出现“这个字段能改、那个不能改”的混合状态。

## 9. 典型任务路径

### 9.1 从零搭建

1. 打开草稿 → 空画布提示把右侧栏顶部的「阶段」拖到画布，或双击空白处。
2. 创建 stage → 自动选中，name 输入框全选，检查器提示“先设置 active roles，或先创建操作”。
3. 在角色面板新增角色 → 角色出现在检查器的角色复选框中。
4. 从对象工具栏把「操作」拖到 stage → 新建 operation，检查器聚焦允许角色；勾选角色即授权，并同时把角色加入 stage 的 active roles；填写显示名和 action。
5. 从 stage 右侧手柄拖到下一个 stage → 新转移被选中，`on` 输入框获得焦点。
6. 填写 `on`；如果是完成路径，拖到 End，并在 action 里写 `result`。
7. 校验通过 → 发布。

### 9.2 调整图的阅读顺序

1. 拖 stage 图形 → 图形移动，画布不动。
2. 状态栏显示“布局已保存”；保存徽标仍是“已保存”，revision 不变。
3. 如果手动排乱了 → `自动布局` 重新排列，画布适应视图；`Ctrl/Cmd+Z` 撤销。
4. 只读页不能调整；拖动图形不响应。

### 9.3 修复校验错误

1. 状态栏和发布按钮旁显示“2 个错误”。
2. 点击校验面板中的错误 → 画布居中到对应 stage，检查器选中对应对象并滚动、聚焦到具体字段。
3. 修改后自动保存 → 校验刷新；错误数量减少。
4. 错误清零 → 发布可用。

### 9.4 处理冲突

1. 另一个标签页保存 → 当前页出现冲突横幅，自动保存停止。
2. 横幅说明服务端 revision，并保留本地修改。
3. 选择“载入服务端版本”或“用我的版本覆盖”；两者都先确认后果。
4. 解决后继续编辑；本地备份仍在，直到成功保存。

### 9.5 审阅版本

1. 版本选择器打开 `v3` → 只读版本页。
2. 选择 `对比 v1` → diff 面板列出变化。
3. 点击一条变化 → 画布选中对应 stage 或在检查器中选中对应对象；被删除的旧对象无法定位时显示说明。
4. 平台流程可以复制到账户；复制后跳到新草稿，并提示引用仍指向源流程。

## 10. 选择模型

### 10.1 可选对象

- stage
- operation
- event
- 进入效果
- 转移（通过边或检查器的 stage 转移列表选中）
- 角色

operation 从画布上的标签选中；event、进入效果和转移从检查器的 stage 列表选中（转移也可以点边选中）。Start/End 标记不是可编辑对象；点击它们只清除选择。可编辑草稿中拖动它们只调整位置，不改变初始 stage 或结束语义。

### 10.2 点击规则

| 点击位置 | 结果 |
|---|---|
| stage 图形 | 选中 stage |
| operation 标签 | 选中该 operation；父 stage 显示“包含选中” |
| 检查器 stage 列表中的事件、进入效果或转移 | 选中该对象 |
| 检查器 `+ 事件`、`+ set_state` 等 | 执行新增；新增操作自己设置选中 |
| 对象工具栏的「阶段」 | 拖动到空白画布新建；单击放到默认位置 |
| 对象工具栏的「操作」「子任务」 | 拖动到 stage；也可以按回车进入放置模式后点击 stage |
| 边 | 选中对应转移；Start 边选中初始 stage |
| Start / End 标记 | 清除选中 |
| 空白画布 | 清除选中 |
| 角色列表项 | 选中角色 |
| 校验项 | 选中并定位对应对象 |
| diff 项 | 选中并定位对应对象；无法定位时禁用 |

### 10.3 选中反馈

- **stage 选中**：图形外圈高亮。
- **event、进入效果和转移选中**：检查器显示对应对象；转移所在的边加粗高亮，父 stage 显示“包含选中”的细外圈。
- **operation 选中**：它的标签加粗、提高对比度；父 stage 同样显示“包含选中”的细外圈。
- **边选中**：边加粗、颜色变为强调色，标签背景加深；父 stage 不强制选中。
- **角色选中**：角色列表项高亮。
- **检查器面包屑**：始终显示当前层级。

行和边没有选中反馈时，用户只能从右侧检查器猜自己选了什么，这是必须补上的基础反馈。

### 10.4 选中与焦点

- 鼠标点击：只改变选中，不把焦点送进检查器。
- 键盘 Enter/Space：选中对象，并把焦点送到检查器的第一个可编辑字段或标题。
- 指针点击后用户按 Tab：焦点按 DOM 顺序进入侧栏，不强制跳转。
- 选中对象消失（删除、外部刷新、撤销后不存在）：回退到最近的父 stage；父 stage 也不存在时清空选择。
- 重排对象后，选中跟随对象移动到新索引，而不是停在原索引。
- 删除对象后，优先选中同位置的下一个对象；没有则选中上一个；再没有则选中父 stage。

### 10.5 不做多选

不做框选、Shift 多选、成组拖动。理由：

- AST 操作没有批量语义；多选后能做的只有删除和移动，删除需要逐个确认引用，收益低。
- 成组拖动只影响布局，而 `自动布局` 已经覆盖“批量整理”。
- 多选会引入框选与平移的冲突、选中集合的撤销语义和检查器的多对象状态，复杂度远高于收益。

## 11. 画布交互

### 11.1 平移和缩放

- 拖空白画布平移；中键拖动和按住空格拖动可以从任意位置平移。
- 滚轮缩放，范围 0.25–2；缩放控件提供放大、缩小、适应画布。
- 不做框选；`selectionOnDrag` 关闭。
- 平移和缩放不保存，不进入撤销历史。
- 缩放时节点和边保持可读；不要在小比例下隐藏文字，避免用户以为内容丢失。

### 11.2 拖动节点

**可拖动区域。** 整个 stage 图形都可以拖动。左侧显示六点 grip，作为“这里可以拖”的明确提示。Start/End 标记整块可拖动（连接手柄除外），光标为 `grab`。

**规则。**

- 只移动当前节点（stage 或 Start/End 标记），不移动其他节点。边会随端点更新，这是连线的必然结果。
- Start/End 有自己的坐标，存在同一份布局里，键为 `__start` / `__end`；移动 stage 不会重算或移动它们。
- 自动布局会同时重排所有 stage 和两个标记；除自动布局外，标记位置不会被其他操作改变。
- 改初始 stage 不会移动 Start 标记，只重连 Start 边。
- 拖动过程中 stage 图形抬升（阴影），光标变 `grabbing`；画布不移动。
- 不吸附网格，不做对齐辅助线；整理用 `自动布局`。
- 松开后位置立即生效，1 秒防抖保存布局。
- 保存成功：状态栏显示“布局已保存 HH:MM”；保存徽标和 revision 不变。
- 保存失败：自动重试 3 次；仍失败时状态栏显示“布局未保存 · 重试”，点击重试。不弹横幅。
- 一次拖动 = 一条撤销记录，记录拖动前后的位置；撤销只写布局，不改变 revision。

**键盘微调。** 选中 stage 且焦点不在输入框、文本域、下拉框或可编辑区域时：

- 方向键移动 10px。
- `Shift` + 方向键移动 1px。
- 连续按键在 500ms 内合并为一条撤销记录。
- 布局保存使用同一个 1 秒防抖。
- 只读模式禁用。

**不拖动的对象。** 检查器里的任何控件、只读模式下的所有节点。Start/End 在可编辑草稿中显示 `grab` 光标，悬停提示“拖动调整位置（只改布局）”；从手柄拖线仍然改变初始 stage 或创建转移。

### 11.3 只读模式下的画布

- stage 图形和 Start/End 标记都不响应拖动；光标默认箭头；悬停提示“只读：不能拖动节点。拖动空白处、按住中键或按住空格平移画布”。
- 隐藏连接手柄。
- 可以点击选中 stage 图形和 operation 标签，查看检查器；从检查器的 stage 列表进入事件、进入效果和转移。
- 点击边可以查看转移详情，但不能编辑。
- 隐藏 `自动布局`；缩放和适应画布保留。

### 11.4 自动布局

- 入口：工具栏 `自动布局`，只读模式隐藏。
- 使用 dagre 从左到右排列全部 stage；自转移不参与布局。
- 执行后画布适应视图，显示消息“已重新布局，可撤销”。
- 一次自动布局 = 一条撤销记录；不产生版本，不影响 revision。
- 不做“每次修改自动重排”。手动布局是用户资产，自动重排会反复破坏它。
- 没有 stage 时按钮禁用。

### 11.5 拉线创建转移

- 每个可编辑 stage 右侧有 source 手柄；左侧有 target 手柄。手柄视觉上是 8px 圆点，命中区域至少 24px。
- 从 stage 右侧拖到另一个 stage：创建 `{ on: "false", action: "", to: target }`。
- 从 stage 右侧拖到 End：创建 `to = "ended"` 的转移。
- 从 Start 拖到 stage：设置 `initial_stage`；如果已有初始 stage，直接改到新目标，并显示“初始 stage 已改为 X”。
- 自转移允许：source 和 target 是同一个 stage。
- 拖到空白处松手：取消，不提示，不创建。
- 拖动过程中，合法目标显示强调色外圈，非法目标变暗；光标为十字。
- 创建后立即选中新转移，检查器打开，`on` 输入框获得焦点，并显示提示“`on` 为 true 时才会沿这条转移进入 `to`”。
- 一次拉线 = 一条撤销记录；撤销后删除该转移并恢复之前的选中。

**为什么默认 `on = "false"`。** 空字符串会立刻产生校验错误并阻塞发布；`"false"` 是合法表达式，明确表示“这条转移还未配置条件”，同时不误触发。用户填好 `on` 后再改成真实条件。

**连接手势不做“拖到空白处自动建 stage”。** 连接手势的目标是可见对象；在空白处松手直接创建 stage 会把“取消”变成“创建”，容易误操作。需要新 stage 时用对象工具栏的「阶段」或双击空白。

**边界。** Start 只有 source，End 只有 target；因此不能创建 End→stage、stage→Start、Start→End 的连接。

### 11.6 删除转移

- 点击边选中转移，检查器显示 `删除转移`。
- 选中转移后按 `Delete` 或 `Backspace` 也可以删除；焦点在输入框中时不拦截。
- 删除后选中按第 10.4 节回退。
- 不在边上加悬浮 `×`；边上的小按钮会遮挡标签并增加误触。

### 11.7 边和标签

- 边标签显示 `on` 的摘要；超过 40 个字符截断为一行，悬停显示完整表达式，选中后在检查器中显示全文。
- `to = ended` 的边标签同样显示 `on` 摘要，终点是 End 标记。
- 同一对 stage 之间有多条转移时，边按顺序做垂直偏移，不能完全重叠；点击每条边选中对应转移。无法偏移时，检查器的 stage 转移列表仍提供逐条入口。
- 选中边时加粗并提高对比度；未选中边保持中性。
- Start 边不可作为转移选中；点击它选中初始 stage，便于查看“初始 stage”设置。

### 11.8 空画布与没有初始 stage

- 没有 stage：画布中央显示引导卡片：“还没有 stage。把右侧工具栏的「阶段」拖到画布，或双击空白处。” 可编辑模式提供按钮；只读模式显示“该流程没有 stage”。
- 有 stage 但没有 `initial_stage`：Start 标记显示“开始（未连接）”，虚线样式；画布上提供一次性提示“从「开始」拖线到初始 stage，或在 stage 检查器里勾选「初始 stage」”。校验面板同时显示错误。
- 初始 stage 被删除或改名后，Start 标记回到“未连接”状态；不要自动选择另一个 stage 作为初始。

### 11.9 stage 图形解剖

```text
┌──────────────────────────────────────────┐ 固定宽度 300
│ ⠿ review  [初始]                          │ 仅 grip、name、初始标记
└──────────────────────────────────────────┘
```

规则：

- 固定宽度 300、固定高度 44；不支持手动调整大小。
- **stage 图形不显示任何内部信息。** 不显示事件、进入效果、转移、active roles、operation 数量或校验徽标，也不显示列表、空状态和底部按钮。图形只表达“这里有一个 stage、它叫什么、是不是初始 stage”。
- 左侧的 grip 只在可编辑模式显示；它和 `grab` 光标一起表达“可拖动”。
- **operation 不进入图形。** 每个 operation 在画布上用 stage 顶边上方的标签表示（见 11.10）。允许发送它的角色不画在画布上，只在检查器显示。
- 事件、进入效果和转移都在右侧检查器中查看和编辑（见 12.3–12.5）。点击 stage 图形打开 stage 检查器，里面按“事件 → 进入效果 → 转移”列出对象；点击列表项进入对应编辑器。
- 校验问题不再显示在图形上；通过校验面板定位。stage 检查器和校验面板仍显示全部错误和警告。
- 不要在图形里加 `+ 事件`、`+ 操作` 或 `+ 转移`，也不要恢复任何行列表。

### 11.10 对象工具栏与 operation 标签

对象工具栏固定在右侧栏顶部，不随画布平移和缩放。可编辑时横向排列三个图形按钮：「阶段」（圆角矩形）、「操作」（圆形播放符号）、「子任务」（方框加向下箭头），图标下附名称；只读时整条工具栏不显示。

- 「阶段」：拖到空白画布，在落点新建 stage；单击则在默认位置新建（见 11.11）。
- 「操作」：拖到 stage 图形或 operation 标签，在该 stage 新建 operation。
- 「子任务」：拖到 stage 图形或 operation 标签，在该 stage 新建 `create_child` 进入效果。workflow 默认取可见流程列表第一项，title 默认“子 Task”。
- 拖动时显示跟随指针的对象图标和提示；stage 作为目标时整块高亮；松在空白、Start/End 或工具栏上取消，不修改 AST，不产生撤销记录。
- 键盘：聚焦工具栏按钮按 Enter/Space；「阶段」立即新建，「操作」「子任务」进入放置模式，再点击 stage 或在聚焦的 stage 上按 Enter/Space；Esc 取消。

**operation 标签：**

- 每个 operation 在所属 stage 顶边上方有一个带图标的胶囊标签，文本优先 `display_name`，为空时回退 `name`，并用短线接到 stage 顶边。
- 不再画角色线。`operation.roles` 不在画布上显示，只在 operation 检查器里显示和编辑。
- 标签始终显示（可编辑和只读都显示），不是转移边；未选中时低对比度，避免和真正的转移抢视觉。
- 标签位置按 operation 在 stage 内的顺序沿顶边分布；相邻标签重叠时向上错开，并用更长的短线接到 stage 顶边。标签默认不覆盖 stage 图形；stage 顶部滚出画布时，标签贴在画布顶部。
- stage 滚出画布时不画对应标签。画布平移、缩放、窗口尺寸变化后重新测量位置。
- 点击标签选中该 operation；检查器显示字段。父 stage 显示“包含选中”的细外圈。标签是按钮，可键盘聚焦；Enter/Space 选中。

**创建与授权：**

- 从工具栏拖入的 operation 初始 `roles = []`。创建后选中新 operation，检查器滚动到允许角色并聚焦第一个角色复选框。
- 勾选角色即授权，并同时把角色加入该 stage 的 `active_roles`；取消勾选只从 operation 移除，不自动移除 stage 的 active role。至少保留一个角色。
- operation 必须有角色，因此刚创建时可能出现“操作至少需要一个角色”的校验错误；这是可见、可立即修复的中间态，不阻止继续编辑或保存草稿。
- 已有 operation 的授权也只在检查器勾选，不提供“把角色拖到标签授权”的第二种手势。
- stage 图形里没有 `+ 操作`。

### 11.11 新 stage 的放置

- 对象工具栏「阶段」拖到空白画布：在落点创建。
- 单击对象工具栏「阶段」：放在当前选中 stage 的右侧 160px、垂直居中；右侧被占用时向下错开。没有选中时放在最右 stage 的右侧。
- 双击空白：在双击位置创建。
- 创建后选中新 stage，画布居中到它，name 输入框全选；新 stage 没有内容，校验会给出 `unreachable_stage` 警告，这是预期的中间态。
- 不要为新建 stage 重排整张图。只有加载到完全没有布局的流程时，才对全部 stage 自动布局。

## 12. 创建流程

### 12.1 创建总则

每个创建动作必须满足：

1. **一个动作完成。** 不弹多步向导。
2. **立即选中新对象。**
3. **焦点落到下一个必须填写的字段。**
4. **一条撤销记录。**
5. **不产生结构上无法保存的 AST。** 语义不完整可以，结构损坏不行。

| 对象 | 入口 | 默认值 | 创建后选中 | 焦点 |
|---|---|---|---|---|
| stage | 对象工具栏「阶段」/ 双击空白 | `stage_N`，无角色、无内容 | 新 stage | name 全选 |
| operation | 对象工具栏「操作」拖到 stage | `operation_N`，display_name 空，roles 空，action 空 | 新 operation | 角色复选框 |
| 子任务 | 对象工具栏「子任务」拖到 stage | `create_child`，默认子流程，title“子 Task” | 新进入效果 | 子流程输入 |
| event | stage 检查器 `+ 事件` | 第一个未使用的事件类型，action 空 | 新 event | action |
| 进入效果 | 检查器 `+ set_state` / `+ create_child` | `set_state: in_progress` 或默认子流程 | 新效果 | 对应字段 |
| 转移 | 从手柄拉线 | `on: "false"`，action 空 | 新转移 | `on` |
| 角色 | 角色面板 | `min_actors: 1`，`max_actors: null` | 新角色 | 角色检查器 |
| 变量 | 任务变量 / stage 变量面板 | 类型 bool，display_name 回退 name | 新变量行 | 新变量名输入 |

### 12.2 operation

- 入口是对象工具栏的「操作」：拖到 stage 图形或 operation 标签新建。stage 图形里没有 `+ 操作`、`+ 事件` 或 `+ 转移`。
- 新建时名称自动生成 `operation_N`，保证同一 stage 内唯一；`roles` 初始为空，检查器聚焦角色复选框。勾选角色后角色同时加入 `active_roles`。
- 没有声明任何角色时，检查器提示先去右侧「角色」面板添加角色；此时 operation 保持无角色并显示校验错误。
- display_name 为空时画布上的 operation 标签回退显示 name；不建议留空，检查器显示“建议填写显示名”的轻提示。
- 名称在失焦/Enter 时提交；非法或重复时保留输入内容，标红并显示“未应用”，按 Escape 恢复原值。
- 删除 operation 不询问；可撤销。删除后选中下一个 operation，没有则上一个，再没有则 stage。
- 角色授权只在检查器勾选；勾选和取消各产生一条撤销记录。

### 12.3 event

- 每个 stage 每种事件最多一个。
- stage 检查器按声明顺序列出全部事件；点击列表项进入事件编辑器。
- `+ 事件` 位于 stage 检查器的事件列表下方，默认选择第一个未使用的事件类型；四种都已使用时按钮禁用，提示“每个 stage 每种事件最多一个”。
- 修改事件类型时，其他事件已占用的选项禁用；当前类型始终可选。
- 添加后聚焦 action 输入框；事件没有角色，也没有过滤条件，action 自己判断是否处理。
- 重复声明在 UI 层阻止，不依赖校验报错。

### 12.4 进入效果

- stage 检查器按声明顺序列出全部进入效果；点击列表项进入效果编辑器。
- `+ set_state` 默认 `in_progress`；`+ create_child` 默认选择可见流程列表的第一项，title 模板为“子 Task”。两个入口都在 stage 检查器；`create_child` 还可以从对象工具栏把「子任务」拖到 stage 创建。
- 添加后选中新效果，聚焦对应字段：set_state 聚焦状态下拉，create_child 聚焦子流程输入。
- 进入效果按声明顺序执行；检查器必须提供上移/下移（当前缺失）。
- 切换类型会替换整个 effect；旧的 set_state 或 create_child 内容丢失。因为这是一次明确的类型切换且可撤销，不弹确认，但撤销标签写“切换进入效果类型”。
- `create_child` 的 workflow 用可输入的下拉（datalist）；输入不存在的 id 时保留输入并在校验中报错，不要静默替换。
- `create_child` 的 title 模板使用标题模板编辑器（见 13.10）。

### 12.5 转移

- 只能通过拉线创建；stage 图形和检查器都没有 `+ 转移` 按钮。stage 检查器的转移列表用于选中和查看已有转移。
- 新转移默认 `on: "false"`、action 空、to 为目标 stage 或 `ended`。
- 创建后立即选中并聚焦 `on`。
- 如果目标是 `ended`，检查器提示“如需返回结果，在 action 中写入 `result`”；不自动生成 action。
- 转移按声明顺序求值，第一条 `on` 为 true 的执行；新转移追加到末尾。检查器提供上移/下移。
- 同一对 stage 之间允许存在多条转移，不自动去重；不同 `on` 指向同一目标是合法设计。

### 12.6 角色

- 角色面板表单：name + 类型（人类/智能体/不限）+ 添加。
- 默认 `min_actors: 1`、`max_actors: null`。
- name 创建后不可修改。原因：`active_actors('role')` 在脚本里以字符串引用角色，改名无法安全重写脚本。需要改名时新建角色、更新引用、删除旧角色；检查器要解释这一点。
- 添加后选中新角色，检查器可编辑类型和数量。
- `max_actors` 留空表示不限；`max_actors < min_actors` 在输入时标红，不等待校验。
- 角色列表显示本地化摘要，例如“人类 · 至少 1 个 actor”“不限 · 1–3 个 actor”。

### 12.7 变量

- 任务变量面板和 stage 变量面板共用同一个编辑器。
- 添加表单：name、类型、显示名；display_name 为空时回退 name。
- name 校验：小写字母开头，只含小写字母、数字、下划线；不能重复；不能是 `result`；任务变量还不能与任何 stage 变量重名，stage 变量不能与任务变量重名。
- `result` 是内置任务级 string 变量，**不在任务变量面板中列出**（RFC 0006 §7.2）；在脚本补全和 `to = ended` 的提示中出现。用户尝试声明 `result` 时直接拒绝并解释“内置变量，不能声明”。
- 类型切换会清空初始值；初始值字段紧邻类型，清空是可见的，并且可撤销，不弹确认。
- `actor_set` 不显示初始值字段。
- 删除变量前扫描 action/on 中是否引用该名称；有引用时列出受影响的字段并确认，没有引用时直接删除。
- 变量改名不自动改脚本；改名后如果脚本仍引用旧名，显示一次非阻塞提示“N 处脚本仍使用旧名称，校验会定位”，由作者手动修改。不要用文本替换冒充重命名。
- 添加后保持焦点在 name 输入框，便于连续添加；新行出现在列表中。

### 12.8 全员确认模板（RFC 缺口）

RFC 0006 §7.5 要求 stage 面板提供“添加全员确认”模板。当前编辑器没有实现。目标交互：

**入口。** stage 检查器的“进入效果”区域下方，作为一个独立的 `添加全员确认` 链接。stage 没有 active roles 时禁用，提示“先为 stage 选择 active roles”。

**参数表单（内联，不弹大向导）。**

- 角色：当前 stage 的 active role 单选。
- operation 名称：默认 `review_approved`，可改；必须在本 stage 内唯一。
- 目标：任意已声明 stage 或 `结束（ended）`。

**生成预览。** 创建前显示将要生成的三项：

1. stage 变量 `approved: actor_set`，display_name“已批准”；名称冲突时变量名和显示名一起加后缀。
2. operation：name 为参数值，display_name“批准”，description 由模板填写，roles 只包含所选角色，action 为 `add event.actor to approved`。
3. 转移：`on` 为 `approved ⊇ active_actors('<role>')`，`to` 为所选目标；没有 action。

**生成后的呈现。**

- 三项都是普通 AST 对象，可以分别编辑、移动、删除；不存在“模板对象”。
- 一次生成 = 一条撤销记录，撤销移除三项。
- stage 检查器的转移列表中，这条转移显示语义标签“所有 {role} 确认后 → {target}”，并带一个“模板”小标记；生成的 operation 仍以画布上的标签显示。
- 检查器选中该转移时，顶部显示“这是全员确认模板生成的转移”，并提供“查看 operation”“查看变量”的跳转；下面是原始的 `on`/`action`，高级用户可以继续改。
- 语义标签是识别结果，不是存储字段。任何一项被改动到不再匹配时，自动回退为普通表达式显示；不要阻止用户编辑。
- 目标是 `ended` 时，提示作者在 transition action 中写入 `result`。
- 转移按顺序求值；如果 stage 已有其他转移，提示“新转移追加在末尾，如需优先判断请上移”。
- 如果 stage 还有其他 active role，提示“模板只允许所选角色发送此 operation；其他角色需要手动加入 roles 和 on”。

### 12.9 创建后的校验预期

新建对象通常会让草稿暂时不完整。编辑器要接受这种中间态，并在检查器和校验面板同时给出下一步：

- 新 stage：`unreachable_stage` 警告；没有初始 stage 时还有初始错误。
- 新 operation：roles 为空（如果 UI 允许中间态）或 action 为空；优先在检查器提示，不弹横幅。
- 新转移：`on = "false"` 不报错，但它永远不会触发；检查器提示它尚未配置。
- 新变量：display_name 回退 name，不报错；被脚本引用前只是声明。

## 13. 检查器：逐对象

### 13.1 检查器外壳

- 顶部：面包屑、对象类型和名称；行对象显示父 stage。
- 没有选中：显示“选择一个对象开始编辑”+ stage 导航列表。列表项包含 name、初始标记、错误/警告数量；超过 12 个 stage 时显示筛选框。点击选中并居中 stage。
- 切换选中：滚动到顶部。
- 定位：滚动到字段并聚焦，字段短暂高亮 1.5 秒。
- 只读：文档式呈现。值用定义列表，脚本用 `<pre>`，角色/变量用列表；不渲染禁用的输入框和按钮。理由：禁用的表单看起来像权限故障，占空间，且不利于阅读和复制。
- 所有表单字段使用 `<label>` 关联；只读字段提供可复制的文本。
- 字段级错误显示在字段下方，`aria-invalid` 标记；不在顶部集中重复。

### 13.2 stage

**字段。**

- `name`：唯一的 stage 标识；没有 display_name。失焦/Enter 提交；非法、重复、`ended` 时保留输入并标红“未应用”，Escape 恢复。
- 改名会同步更新 `initial_stage` 和所有 `transition.to`；图形位置保持不变（迁移布局 key，不重新自动布局）。
- `初始 stage` 复选框：同一时间只有一个；取消勾选后允许草稿暂时没有初始 stage，校验报错。也可以用 Start 拉线设置。
- `active roles`：复选框列表；没有角色时显示“尚未声明角色”+“去添加角色”链接，滚动到角色面板。
- 移除一个被 operation 引用的 active role 时，先确认并列出受影响的 operation；确认后 operation 的 roles 中保留该名称并显示为无效标签，由用户逐个移除或重新加回角色。
- stage 变量：见 12.7；在 stage 检查器里编辑。
- 进入效果：列表项可点击选中；“+ set_state”“+ create_child”；上移/下移。
- 删除 stage：
  - 被其他 stage 的 transition 指向时禁用删除，列出引用（可点击定位到对应转移）。
  - 是初始 stage 但没有入边时允许删除，确认“删除后流程没有初始 stage，需要重新指定”；确认后清空 `initial_stage`。
  - 删除有内容的 stage 时确认，列出将一起删除的 operation/event/进入效果/转移数量。
  - 删除后选中清空。

**只读。** 名称、初始状态、角色、变量、进入效果都以文档形式展示；不显示删除。

### 13.3 operation

**字段。**

- `name`：同一 stage 内唯一；失焦/Enter 提交，重复/非法时保留输入并标红。
- `display_name`：画布上 operation 标签的主文本；建议填写。
- `description`：展示给发送者；多行文本。
- `roles`：列出流程声明的全部角色，多选；至少一个。勾选角色会同时把它加入当前 stage 的 `active_roles`；取消勾选只从 operation 移除。这是唯一的授权手势，画布上没有角色线。
  - 只剩一个已选角色时，该复选框禁用，提示“至少保留一个角色；如需停用此操作，请删除操作”。
  - 如果 operation.roles 中存在已不在 `active_roles` 的角色（旧数据或移除角色后），显示为红色无效标签，带 `×` 移除；不要隐藏。
  - 没有任何流程角色时，提示先去右侧「角色」面板添加角色。
- `action`：脚本编辑器（见 13.11）。

**排序/删除。** 上移/下移；删除后选中下一个，没有则上一个，再没有则 stage。删除不确认，可撤销。

**只读。** 文档式展示所有字段；action 用代码块。

### 13.4 event

- `event` 下拉：四种类型；已被本 stage 其他 event 使用的选项禁用。显示中文释义，例如 `child.state_changed（子任务状态变化）`。
- `action`：脚本编辑器；事件没有角色。
- 上移/下移、删除规则同 operation。
- 检查器根据事件类型显示可用的 `event.*` 字段提示（见 13.11）。

### 13.5 进入效果（created）

- 类型：`set_state` 或 `create_child`。
- `set_state`：`pending（待处理）` / `in_progress（进行中）`；不提供 `completed`。
- `create_child`：子流程 id（datalist 可输入）、标题模板编辑器。
- 上移/下移（当前缺失）；删除不确认，可撤销。
- 顺序有意义：每次进入 stage 按声明顺序执行；检查器注明“按顺序执行”。
- `create_child` 的 workflow 必须能在所有者作用域内解析；输入未知 id 时保留输入并让校验报错，不自动改成别的流程。

### 13.6 转移

- `on`：必填的非空 boolean 表达式；脚本编辑器。
- `action`：可选语句脚本；在 `on` 匹配后、进入 `to` 前执行。
- `to`：所有 stage + `结束（ended）`；当前 stage 自己也在列表中（自转移）。
- 目标不存在（旧数据）时显示“X（不存在）”并标红，不要静默改成第一个 stage。
- 上移/下移；转移按顺序求值，第一条 true 执行。
- 删除不确认，可撤销；边随之消失。
- 新建转移的提示：`on` 为 true 才生效；`to = ended` 时提示写 `result`。
- 自转移提示：会重新进入当前 stage，stage 变量重置，进入效果重跑。
- 同一对 stage 多条转移时，检查器显示“本 stage 到 target 共 N 条”，避免用户以为边丢了。

### 13.7 角色

- `name`：只读，创建后不可改（原因见 12.6）。
- 类型：人类/智能体/不限。
- `min_actors`：≥0；`max_actors`：空表示不限；max < min 时标红。
- 删除：被 `active_roles`、operation.roles 或 `active_actors('<name>')` 脚本引用时禁用，列出引用（可点击定位）。删除不可用时不弹确认。
- 只读：文档式展示。

### 13.8 任务变量

- 面板始终可见；跨 stage 保留。
- 每个变量编辑 name、display_name、类型、初始值；添加、删除。
- 不列出 `result`；在面板说明“`result` 是内置任务级 string 变量，在脚本和完成路径中使用”。
- 名称不能与任何 stage 变量重名；添加/改名时立即检查并提示冲突的 stage。
- 删除前扫描所有 stage 的 action/on；列出受影响的字段并确认。
- 只读：文档式列表，显示 display_name 为主、name 和类型为次。

### 13.9 stage 变量

- 位置：stage 检查器。
- 每次进入 stage（包括自转移）按声明重新初始化，离开后丢弃；面板要写明这一点。
- 名称不能与任务变量或其他 stage 变量重名；不能是 `result`。
- 删除前扫描当前 stage 的 action/on；列出受影响字段并确认。
- 只读：文档式列表。

### 13.10 标题模板

- 用于 `create_child.title`。
- 按片段编辑：文本、`{task.title}` 字段、`{count_children('workflow') + offset}` 计数。
- 每个片段可删除；底部提供 `+ 文本`、`+ 字段`、`+ 计数`。
- 预览显示原始模板文本；模板无法解析时显示错误和原始输入，允许继续编辑。
- 计数片段的 workflow id 使用可见流程列表；没有可选项时不要伪造 `project`，留空并显示错误。
- 限制：模板源码最多 500 字符，生成标题最多 200 字符且不能为空；超限由校验报错。

### 13.11 脚本字段（RFC 缺口）

RFC 0007 §11 规定的目标编辑器：

- `action` 使用 program 模式；`on` 使用 expression 模式。
- 语法高亮、按上下文补全、行列诊断、代码片段。
- 不提供在编辑器中执行脚本的能力。
- 补全只提示当前作用域可用的变量、`task.state`、`task.title`、`active_actors`、`count_children`、`result` 和字面量。
- `on` 不提示任何 `event.*`。
- operation action 提示 `event.actor`；event action 只提示当前事件类型可用的字段；transition action 不提示 `event.*`。
- 诊断来自服务端校验，显示在对应行列；不在客户端另写一套解析器作为权威。

当前实现是纯文本 textarea。在富编辑器落地前，最低要求：

- 等宽字体、关闭拼写检查、保留换行。
- 字段上方或下方显示“可用变量”清单，按当前上下文列出 task 变量、stage 变量、`result` 和内置函数；点击名称插入到光标处。
- 显示当前事件的字段表（见下）。
- 校验错误通过路径定位到字段；如果错误消息包含行列，显示行列。
- 不劫持 Tab；Tab 仍然移动焦点。缩进用两个空格，用户自己输入。

**作用域速查。**

| 上下文 | 可读 |
|---|---|
| 所有 action / `on` | task 变量、当前 stage 变量、`result`、`task.state`、`task.title`、`active_actors('role')`、`count_children('workflow')`、字面量 |
| operation action | 额外：`event.actor` |
| `task.created` action | 无额外字段 |
| `task.state_changed` action | 额外：`event.state` |
| `child.created` action | 额外：`event.child.id`、`event.child.workflow`、`event.child.title` |
| `child.state_changed` action | 额外：`event.child.id`、`event.child.workflow`、`event.child.state`、`event.child.result` |
| transition action | 无 `event.*` |
| transition `on` | 无 `event.*`；必须返回 boolean |

`result` 只在脚本和完成路径中出现，不在任务变量面板中列出。

### 13.12 删除和排序总则

| 对象 | 删除确认 | 删除后选中 | 排序 |
|---|---|---|---|
| operation | 否 | 下一个 → 上一个 → stage | 上移/下移 |
| event | 否 | 同上 | 上移/下移 |
| 进入效果 | 否 | 同上 | 上移/下移 |
| 转移 | 否 | 同上 | 上移/下移 |
| 变量 | 有脚本引用时确认 | 下一个变量 → 上一个 → 无 | 无（声明顺序不参与语义） |
| 角色 | 被引用时禁用 | 下一个角色 → 无 | 无 |
| stage | 有内容/是初始时确认；有入边时禁用 | 清空 | 无 |

共同规则：

- 重排后选中跟随对象，不跟随索引。
- 删除后按“下一个 → 上一个 → 父级”回退。
- 有引用的对象不静默级联删除；列出引用并让用户先处理。
- 所有可逆删除不弹确认；确认只用于会丢失大量内容、会覆盖他人修改或无法撤销的操作。

## 14. 校验、定位与发布

### 14.1 校验时机

- 打开编辑器时校验一次。
- 每次草稿保存成功后校验一次。
- 修改未保存时，面板保留上一次结果，并显示“基于已保存版本；当前修改保存后重新校验”。不要用旧结果阻塞发布。
- 校验请求失败时显示“校验请求失败，结果可能不是最新”+ 重试；不要静默保留旧结果。
- 不做每次按键的实时校验，避免请求风暴和界面闪烁；600ms 自动保存已经提供了接近实时的反馈。

### 14.2 校验面板

- 标题：`校验 · 2 个错误 · 1 个警告`，或 `校验 · 通过`。
- 错误在前，警告在后；每条显示路径和消息，整条可点击。
- 错误阻止发布；警告不阻止，但发布后要显示。
- 没有错误和警告时显示“通过，没有错误或警告”。
- 校验进行中显示“正在校验…”，保留旧列表但降低对比度。
- 面板顶部说明“点击定位到流程图和字段”。

### 14.3 定位行为

点击校验项或 diff 项时：

1. 选中对应对象；父 stage 不存在时显示“该位置已不存在，校验结果可能已过期”。
2. 画布居中到 stage，按当前缩放级别，不突然改变缩放。
3. 行/字段高亮 1.5 秒；尊重 `prefers-reduced-motion`。
4. 检查器滚动到字段并聚焦：
   - `stages[i].operations[j].action` → operation 的 action 输入框。
   - `stages[i].transitions[j].on` → 转移的 `on` 输入框。
   - `stages[i].transitions[j].to` → `to` 下拉。
   - `stages[i].vars.<name>` → 变量行。
   - `roles[i]` → 角色检查器。
   - `vars.<name>` → 任务变量面板中的变量行（滚动并高亮，不改变选中类型）。
   - `initial_stage` → Start 标记和首个 stage 的初始复选框；显示“未设置初始 stage”提示。
5. 无法映射到具体字段时，至少选中对象并滚动到对应面板；不要静默无反应。

### 14.4 发布按钮和原因

按钮旁边始终显示原因，而不是只放在 `title`：

| 状态 | 按钮 | 旁边显示 |
|---|---|---|
| 只读 | 隐藏 | `只读` 徽标 |
| 发布中 | 禁用 | `发布中…` |
| 冲突 | 禁用 | `存在草稿冲突` |
| 保存失败且不可重试 | 禁用 | `保存失败，先重试保存` |
| 当前已保存内容有校验错误 | 禁用 | `N 个校验错误`，可点击定位 |
| 有警告 | 可用 | `N 个警告`（不阻止） |
| 正常 | 可用 | 无 |

- 已保存内容有错误才禁用；过期校验结果只作提示，不阻塞。
- 修改未保存不阻塞：点击发布先 flush，再发布。
- 发布按钮禁用时仍然可以被聚焦，屏幕阅读器能读到原因文本。

### 14.5 发布流程

1. 点击发布。
2. 如果有未保存修改，先 flush；保存失败或冲突则停止，显示原因。
3. 调用发布接口；服务端重新执行完整校验（RFC 0005 §10.5）。
4. 校验错误：停在编辑器，显示错误面板，选中并定位第一条错误；不产生版本，草稿不变。
5. 冲突：显示冲突横幅。
6. 成功：显示“已发布 vN · 时间”，提供“查看版本”（新标签页）；刷新版本列表；采用新 revision；草稿继续可编辑。
7. 有警告：成功横幅注明“N 个警告”，校验面板保留警告列表。

### 14.6 发布后

- 保存徽标回到“已保存”。
- revision 更新，避免下一次自动保存和自己冲突。
- 版本选择器出现新版本。
- 不自动跳转版本页；用户继续编辑草稿。
- “查看版本”在版本页显示刚发布的 AST；布局使用当前共享布局。

## 15. 自动保存、冲突与恢复

### 15.1 保存状态机

| 状态 | 徽标 | 含义 | 用户可做什么 |
|---|---|---|---|
| saved | 已保存 | 服务端草稿与当前 AST 一致 | 继续编辑；发布 |
| dirty | 未保存 | 有修改，等待 600ms 防抖 | 继续编辑；Ctrl/Cmd+S 立即保存 |
| saving | 保存中 | 保存请求在途 | 继续编辑；再次保存会排队 |
| retrying | 保存失败，重试中 | 网络/5xx，指数退避 | 等待；手动保存 |
| failed | 保存失败 | 4xx 等不可重试错误 | 修复问题后重试；查看消息 |
| conflict | 冲突 | revision 不一致，自动保存停止 | 处理横幅 |

- 保存状态变化通过 `aria-live="polite"` 宣布；冲突和错误用 `assertive`。
- 状态栏显示最近一次成功保存的时间，例如“已保存 · 14:32”。
- 布局状态独立，不进入这张表（见 7 和 11.2）。
- 保存失败的非重试状态不要显示“重试中”；这是两种不同状态。

### 15.2 冲突

冲突横幅内容：

- 说明服务端 revision 和“自动保存已停止”。
- 说明本地修改仍保留在编辑器中，并写入了本地备份。
- 两个动作，都先说后果：
  - **载入服务端版本**：确认“将丢弃当前编辑器中的本地修改，载入服务端草稿（revision N）”。确认后清空选择、刷新校验、重置保存器。
  - **用我的版本覆盖**：确认“将用当前编辑器内容覆盖服务端草稿（revision N）。服务端较新的修改会丢失，不会自动合并”。确认后以服务端当前 revision 重新提交。
- 不做字段级合并，不做自动重试。
- 可选增强：在横幅里展开“查看差异”，用现有 diff 逻辑列出本地与服务端的差异，帮助用户选择；不改变两个动作的语义。

### 15.3 本地备份恢复

- 每次本地编辑后立即写入 localStorage 备份（防抖前）；保存成功、发布成功或明确丢弃后清除。
- 打开编辑器时，如果备份 body 与服务端草稿不同，显示恢复横幅：
  - 备份时间。
  - 备份基于的 revision，以及服务端当前 revision。
  - 如果备份 revision 小于服务端 revision，明确提示“恢复后会覆盖服务端较新的修改”。
- **恢复未保存的修改**：确认“恢复会替换编辑器当前内容，并在随后自动保存到服务端”；确认后应用，标记 dirty，进入正常自动保存。可撤销。
- **丢弃本地备份**：只清除本地备份，不影响服务端草稿；不需要确认。
- 可选增强：展开备份与服务端草稿的 diff 摘要。

### 15.4 离开页面和切换版本

- 页面隐藏或 `pagehide`：如果有未保存 AST，发送 keepalive 保存；布局也 flush（布局接口需要支持 keepalive 或至少同步发起）。
- 有未保存 AST：注册 `beforeunload` 提示。
- 切换到历史版本或返回流程列表前：先 flush AST 和布局；flush 失败时询问“仍有未保存修改，仍要离开？”，不静默丢弃。
- 版本页是只读快照；离开草稿不会丢失已保存内容。

## 16. 版本页与对比

### 16.1 版本页结构

- 工具栏：返回流程、标题、`历史版本（只读）`、`只读 · vN`、版本选择器、对比选择器、发布者和时间、`返回草稿`（仅可编辑者）、`复制到我的账户`（仅平台流程）。
- 画布：完整只读流程图；stage 图形不可拖动；没有手柄。
- 侧栏：检查器、任务变量、角色；都使用文档式只读呈现。版本页不重新校验发布时的警告（警告不随版本保存）。
- 状态栏：`版本 vN 不可编辑` + stage/角色数量。

### 16.2 版本选择器

- 当前版本在选项中选中；不再出现“草稿”伪选项。
- 只读编辑器（非版本页）显示 `只读 · vN`，版本选择器当前项是 vN；没有已发布版本时显示 `只读 · 未发布`，选择器禁用。
- 版本页的对比选择器在只有一个版本时禁用，提示“没有其他版本可对比”。

### 16.3 对比

- 选择基准版本后，diff 面板显示 `vBase → vTarget`，按语义列出变化。
- 按 scope 分组（stage、角色、任务变量、初始 stage、schema），每组显示变化数量；组内按 AST 顺序。
- 每条显示“新增/删除/修改”和具体对象；点击定位。
- 修改 task 变量时滚动到任务变量面板并高亮变量行；修改 stage 变量时选中 stage 并高亮变量行。
- 删除的对象无法在当前画布定位时禁用并显示“已删除，无法定位”；如果父 stage 仍存在，选中父 stage 并说明。
- 加载中显示“正在载入对比版本…”；失败显示错误；无变化显示“两个版本的流程定义一致”。
- 对比只覆盖 AST，不包含标题、布局和运行期数据。

### 16.4 复制到我的账户

- 仅平台流程显示。
- 标题输入默认“原标题（副本）”，必须非空；按钮在复制中禁用。
- 复制是逐字复制，**不重写引用**：`create_child.workflow` 和 `count_children` 中指向源流程的字符串仍指向源流程。复制成功跳到新草稿后，显示一次非阻塞提示“副本中的流程引用仍指向源流程，请按需手动修改”。
- 新流程是账户流程，有独立 id、草稿和布局；与源流程不共享状态，不跟随源流程更新。
- 复制失败显示错误；401 走会话失效处理。

### 16.5 布局与版本

- 版本页使用当前共享布局；布局不属于版本，所以同一版本在不同时间打开可能位置不同。
- 版本中新增/删除的 stage 由布局合并规则处理：缺失位置自动布局，多余位置忽略。
- 版本页不提供“自动布局”；布局是共享元数据，只读用户不应修改。

## 17. 键盘与无障碍

### 17.1 快捷键

| 快捷键 | 动作 | 范围 |
|---|---|---|
| `Ctrl/Cmd+S` | 立即保存草稿 | 全局，输入框内也生效 |
| `Ctrl/Cmd+Z` | 撤销 | 焦点不在输入框/文本域/下拉框/可编辑区域 |
| `Ctrl/Cmd+Shift+Z` 或 `Ctrl/Cmd+Y` | 重做 | 同上 |
| `Escape` | 取消连接 / 清除选择 / 关闭对话框 / 名称输入恢复原值 | 全局 |
| 方向键 | 选中 stage 时微调 10px | 可编辑，焦点不在表单控件 |
| `Shift` + 方向键 | 微调 1px | 同上 |
| `Delete` / `Backspace` | 删除选中的行、转移或角色；stage 走删除按钮/确认流程 | 可编辑，焦点不在表单控件 |
| `C` | 键盘连接：从选中 stage 打开目标选择器 | 可编辑 |
| `Enter` / `Space` | 在画布节点或行上选中，并把焦点送入检查器 | 全局 |

在输入框、文本域、下拉框中，撤销/重做交给浏览器，不修改整个 AST。这个规则要在快捷键提示和帮助里写清楚，避免用户以为全局撤销失灵。

### 17.2 键盘连接（拖拽的替代）

鼠标/触控下转移只能拉线；键盘用户需要等价路径：

1. 选中一个 stage。
2. 按 `C` 打开一个小型目标选择器，列出所有 stage 和 `结束（ended）`。
3. 用方向键选择，Enter 确认，Escape 取消。
4. 创建与拉线相同的转移，选中并聚焦 `on`。

这不是界面上第二个“+ 转移”按钮，而是同一手势的键盘等价物。Start→stage 的初始设置已由 stage 检查器的“初始 stage”复选框覆盖，不需要额外键盘路径。

### 17.3 焦点规则

- 指针点击不抢焦点；键盘 Enter/Space 激活才把焦点送进检查器。
- 画布开始处提供视觉隐藏的“跳到检查器”跳过链接，聚焦时可见。
- 对话框：初始焦点在安全的“取消”按钮；Esc 取消；Tab 循环限制在对话框内；危险按钮需要明确聚焦后按 Enter。
- 定位后焦点落在具体字段；不要只选中对象而不移动焦点。
- 关闭检查器对象（点击空白）时，焦点回到画布，不落到 `body`。

### 17.4 屏幕阅读器和视觉

- 画布节点设置 `aria-label`：`stage review，初始`。
- 检查器 stage 列表中的对象按钮，其文本包含类型和名称/目标。
- 边可聚焦，`aria-label` 为 `转移：on ...，前往 ...`。
- 保存状态、布局状态、校验数量用 `aria-live`；冲突和错误用 `alert`。
- 图标按钮必须有 `aria-label`（删除、关闭、放大、缩小、适应画布）。
- 不能只用颜色表达状态：校验项显示错误/警告数量，选中状态同时有外圈、描边或背景变化。
- 焦点环在浅色和深色主题下都清晰；不要移除 `:focus-visible`。
- 支持 `prefers-reduced-motion`：关闭定位闪烁动画和 stage 图形抬升过渡，保留即时状态变化。
- 只读页面的文本可选中、可复制；脚本用 `<pre>` 保留格式。

### 17.5 触控和窄屏

- 桌面优先；窄于 900px 时侧栏移到画布下方，画布保持至少 50vh 高度。
- 触控支持单指拖动 stage、双指缩放/平移（由 React Flow 提供）；不设计专门的移动端工具栏。
- 只读模式在触控上允许单指平移画布（没有中键和空格）；stage 图形本身仍不移动位置。
- 不把关键操作藏在悬停里；悬停提示只是补充。

## 19. 反馈、动效和文案

### 19.1 反馈层级

| 层级 | 用途 | 例子 |
|---|---|---|
| 字段内 | 输入校验 | 名称非法、max < min、display_name 冲突 |
| 状态栏 | 持续状态、瞬时结果 | 已保存、布局已保存、2 个错误 |
| 校验面板 | 对象级问题 | stage 上 2 个错误、1 个警告 |
| 横幅 | 需要决策或跨对象的错误 | 冲突、恢复、发布失败 |
| 对话框 | 破坏性确认 | 覆盖服务端、载入服务端、删除有内容的 stage |
| 画布内联提示 | 手势引导 | 空画布、未连接 Start、只读提示 |

不要用 toast 承载需要用户决策的信息；toast 会自动消失，用户可能错过。

### 19.2 动效

- 拖动：stage 图形抬升阴影，120ms；不缩放，避免抖动。
- 定位：目标对象/字段高亮 1.5 秒，淡出；减少动态时直接切换。
- 布局保存：状态栏文字切换，不做闪烁。
- 选中：边框/背景即时变化，不超过 120ms。
- 连接：合法目标外圈出现，非法目标变暗；不要做长动画。
- 所有动效尊重 `prefers-reduced-motion`。

## 20. 明确不做

| 不做 | 理由 |
|---|---|
| 多选/框选/成组拖动 | 没有批量 AST 语义；只对布局有用，自动布局已覆盖；复杂度和误操作成本高 |
| stage 图形手动调整大小 | 固定宽度和高度；调整大小会引入布局和文本截断问题 |
| 小地图 | 当前规模用缩放和适应画布足够；小地图增加视觉噪音 |
| 拖拽对象排序 | 检查器提供上移/下移和键盘路径；画布拖拽会和 stage 拖动冲突 |
| 每个 stage 单独自动布局 | 只保留全局自动布局，避免出现“局部排版覆盖全局”的状态 |
| 布局冲突合并 | 布局是展示元数据，last-write-wins；不值得为它引入 revision |
| 每次编辑自动重排 | 会反复破坏用户的手动布局 |
| 画布上的自由批注、便签、容器 | 不属于 AST，无法进入版本和校验；会变成第二套真相 |
| 在只读视图显示运行期变量值 | 只读展示的是定义，不是某个 Task 的运行状态 |
| 脚本的本地执行 | 运行时语义只能由解释器和服务端校验决定 |
| 独立 toast 系统 | 反馈层级已经够用；toast 会漏掉需要决策的信息 |
| 移动端优先布局 | 编辑器是桌面工具；窄屏只保证可用 |
| 多人实时协同/CRDT | 草稿是共享单副本，冲突显式处理；实时协同是另一个产品问题 |
| stage 的 display_name | 领域规定 stage 只有 name；不要用 UI 发明第二个身份 |
| 角色改名 | 脚本用字符串引用角色；改名无法安全重写 |
| `terminal` stage | `ended` 是虚拟完成目标，不是 stage |
| `+ 转移` 按钮 | 转移只能通过拉线创建；键盘等价物是 `C` 命令，不是第二个可见入口 |
| 拖到空白自动创建 stage | 会把取消手势变成创建手势，容易误操作 |
| 边的悬浮删除按钮 | 遮挡标签、增加误触；用检查器和 Delete |
| click-click 连接模式 | 与拉线并存会产生两种连接模式；键盘路径已经覆盖无障碍需求 |

## 22. 实施顺序

### 阶段 1：消除误判和基础反馈（P0）

1. stage 图形 grip、拖动区域、光标；只读图形不响应拖动。
2. 模式信号统一：徽标、检查器新增入口、手柄、检查器样式。
3. operation/父 stage/边/角色的选中反馈。
4. 只读文档式呈现；版本页补任务变量。
5. 发布原因常驻；冲突/恢复确认。

### 阶段 2：编辑流和安全性（P1）

1. 定位居中、闪烁、字段聚焦。
2. 重排选中跟随、删除回退、进入效果排序。
3. 事件上限、operation 角色、无效角色标签。
4. 新 stage 放置和居中；改名保留位置。
5. 空画布、无初始 stage、`result`、任务变量冲突、删除变量引用。
6. 保存失败区分、校验新鲜度、布局保存失败提示。

### 阶段 3：效率和可访问性（P2）

1. 撤销合并/标签/布局历史；空按钮禁用。
2. 键盘微调、Delete、Esc、`C` 连接、跳过链接。
3. 双击空白创建。
4. 校验面板定位到检查器中的具体对象。
5. 并行边偏移、边标签截断、Start 边点击。
6. 版本选择器、对比分组、复制提示、布局 flush。

### 阶段 4：RFC 缺口

1. 脚本编辑器按 RFC 0007 §11：高亮、补全、诊断、片段。
2. 全员确认模板（RFC 0006 §7.5）和语义标签（§7.6）。
3. 冲突和恢复的 diff 预览（可选）。

## 23. 验收场景

以下场景用于验收交互，不替代单元测试。

### 23.1 可编辑草稿拖动

1. 以所有者/平台管理员打开草稿，确认徽标是“草稿”、对象工具栏可见、stage 图形手柄可见、光标是 `grab`。
2. 拖动 stage 图形 200px。图形跟随，画布视口不移动；保存徽标保持“已保存”；revision 不变；状态栏显示布局已保存。
3. 刷新页面，位置保留。
4. 选中 stage，方向键移动 10px，Shift+方向键移动 1px；撤销回到拖动前位置。
5. 撤销/重做按钮的提示显示动作名；历史为空时禁用。

### 23.2 只读拖动

1. 打开历史版本页，确认徽标“只读 · vN”、没有对象工具栏、没有 stage 图形手柄、图形光标是默认箭头。
2. 拖动 stage 图形：图形不移动，画布不移动。
3. 拖空白、按中键拖、按住空格拖：画布平移。
4. 点击 stage 图形和 operation 标签：检查器显示只读文档，没有禁用输入框；stage 检查器能看到事件、进入效果和转移列表。
5. 非所有者的平台流程编辑器同样表现。

### 23.3 Start/End

1. 拖动 Start/End：只移动该标记，其他 stage 和另一个标记不动；布局保存。
2. 拖动 stage：Start/End 保持原位，边随端点更新。
3. 从 Start 拉线到 stage：初始 stage 设置；之前的“初始”标记消失；Start 边移动；标记位置不变。
4. 点击 Start 边：选中初始 stage。
5. 只读模式拖动 Start/End：不移动、不平移画布。
6. 没有初始 stage 时，Start 显示“未连接”，画布有内联提示。

### 23.4 拉线创建转移

1. 从 stage 右侧手柄拖到另一个 stage：新转移出现，检查器打开，`on` 获得焦点，提示条件生效规则。
2. 拖到 End：`to = ended`；检查器提示写 `result`。
3. 拖到自身：自转移；提示 stage 变量重置、进入效果重跑。
4. 拖到空白松手：无变化、无提示。
5. 只读模式没有手柄。
6. 撤销删除新转移并恢复之前的选中。

### 23.5 创建

1. 对象工具栏显示「阶段」「操作」「子任务」。把「阶段」拖到画布空白处：新 stage 在松手位置创建，画布居中，name 全选。单击「阶段」：在默认位置（选中 stage 右侧或最右 stage 右侧）创建。
2. 双击空白：stage 在双击位置创建。
3. 把「操作」拖到 stage：新 operation 选中，display_name 聚焦；`roles` 为空，检查器列出全部角色并聚焦第一个角色复选框；画布上没有角色线。勾选角色后 `operation.roles` 和该 stage 的 `active_roles` 都包含该角色；撤销同时恢复两处修改。
4. 单击「操作」进入放置模式，再点击 stage（或聚焦 stage 后按 Enter/Space）：效果与拖拽相同；`Esc` 取消放置模式。
5. 把「子任务」拖到 stage：新增 `create_child` 进入效果并选中，workflow 字段聚焦。单击「子任务」再点 stage 同样有效。
6. 在 stage 检查器点 `+ 事件` 直到四种事件用尽：按钮禁用，选项禁用。
7. `+ set_state` / `+ create_child`：新效果选中，对应字段聚焦；上移/下移可用。
8. 添加角色/变量：表单保持焦点，可连续添加；新对象出现在列表。
9. stage 图形内没有任何内部信息，只有 name 和初始标记；每个 operation 在图形上方有一个带图标的标签，不显示 `roles`，也没有角色线。点击标签选中 operation，点击图形其他位置仍选中 stage；只读视图同样如此。
10. 点击 stage 图形，检查器列出事件、进入效果和转移；点击任一项进入对应编辑器，面包屑可返回 stage。

### 23.6 删除和重排

1. 选中 operation，Delete：删除，选中下一个；撤销恢复并选中它。
2. 上移 operation：选中跟随该 operation，不跳到另一个。
3. 删除被入边引用的 stage：按钮禁用，引用可点击定位。
4. 删除初始 stage 且没有入边：确认后清空初始标记，校验提示重新指定。
5. 删除被引用的变量：列出受影响的 action/on；确认后删除；校验定位。

### 23.7 校验和定位

1. 写一个非法脚本并保存：校验面板显示错误和路径。
2. 点击错误：画布居中 stage，检查器选中对应对象，action/on 输入框获得焦点。
3. 修改未保存时，面板显示“基于已保存版本”；保存后刷新。
4. 校验请求失败：显示失败提示和重试，不静默保留旧结果。
5. 发布按钮旁显示错误数量；修正后数量清零，发布可用。

### 23.8 自动保存和冲突

1. 修改后 600ms 自动保存；Ctrl/Cmd+S 立即保存；状态徽标变化正确。
2. 两个标签页编辑同一草稿：后保存者看到冲突横幅，自动保存停止，本地修改保留。
3. 点击“载入服务端版本”：先确认，确认后丢弃本地修改并刷新。
4. 点击“用我的版本覆盖”：先确认，覆盖后状态恢复。
5. 关闭页面时若有未保存 AST 或布局，浏览器提示/keepalive 保存。

### 23.9 恢复备份

1. 修改后在保存前关闭页面；重新打开：显示备份横幅，包含时间、备份 revision、服务端 revision。
2. 恢复：确认后内容替换并自动保存；可撤销。
3. 备份 revision 较旧时：明确警告会覆盖服务端较新修改。
4. 丢弃：只清除本地备份，服务端不变。

### 23.10 发布

1. 有校验错误时发布按钮禁用，旁边显示错误数量；点击数量定位。
2. 修正后发布：先 flush，再发布；成功横幅显示版本号和时间，提供“查看版本”。
3. 发布后 revision 更新，继续编辑不会立刻冲突；版本选择器出现新版本。
4. 发布返回 409：显示冲突横幅。
5. 发布返回校验错误：显示面板并定位第一条错误，不产生版本。

### 23.11 版本页和对比

1. 版本页显示 `只读 · vN`、发布者、时间、完整只读图、任务变量和角色。
2. 版本选择器当前项是 vN，没有“草稿”伪选项；只有一个版本时对比选择器禁用。
3. 选择一个基准版本：diff 按 scope 分组；点击变化定位到画布/检查器/任务变量。
4. 删除的对象无法定位时显示说明，按钮禁用。
5. 平台流程复制：默认标题“原标题（副本）”；复制后跳到新草稿，并提示引用仍指向源流程。

### 23.12 键盘和无障碍

1. Tab 能到达画布节点、行、边和侧栏控件；焦点环可见。
2. 在 stage 上按 Enter：选中并聚焦检查器；方向键微调。
3. 按 Escape：取消连接/清除选择/关闭对话框；名称输入恢复原值。
4. 选中 stage 按 `C`：目标选择器打开，选择目标后创建转移并聚焦 `on`。
5. 屏幕阅读器能读到保存状态、冲突、发布错误和节点标签。
6. 开启“减少动态效果”后，定位不闪烁，拖动无过渡。

### 23.13 布局和版本的边界

1. 拖动 stage 后立即打开历史版本：布局 flush 后打开；版本页使用共享布局。
2. 发布只改变 AST 版本，不改变布局；版本页位置来自当前布局。
3. 只读页没有“自动布局”；缩放和适应画布可用。
