# ADR 0002：控制平面形态

- 状态：Accepted
- 日期：2026-11-02

## 背景

目标是让 AI 承担软件工程的大部分执行工作，人类保留观察和关键决策权。可选形态包括：

1. IDE 插件 / 提示词框架；
2. Jira 克隆，增加 AI 字段；
3. 自托管的、API 优先的软件工程控制平面。

前两者都无法成为“所有工程动作的必经入口”。插件只能约束使用插件的智能体；Jira 克隆把 AI 当成一种用户，无法表达证据、租约、工具权限和预算。

## 决定

Foundry 是一个**自托管、API 优先的控制平面**，形态上更接近 GitHub + Kubernetes，而不是 Jira + IDE 插件。

- 人类入口：Web 控制台、CLI、Git。
- 智能体入口：HTTP API、MCP 工具。
- 外部执行面：Git、CI、沙箱、部署、聊天、模型推理。Foundry 不自己跑模型，也不自己执行构建；它负责授权、记录、验证和阻断。
- Git 是文本内容的真相源；Postgres 是运行状态的真相源；事件日志是审计的真相源。

## 三层约束

| 层 | 约束什么 | 机制 |
|---|---|---|
| 流程 | 能不能进入下一状态 | 状态机 + 证据门禁 + 审批 |
| 动作 | 能调用哪些工具、改哪些资源 | 策略引擎 + capability token + 工具网关 + 沙箱 |
| 资源 | 能用多少 | 预算、配额、速率限制、租约超时 |

## 不做什么

- 不做通用聊天工具；聊天是执行面之一。
- 不做代码编辑器；代码在 Git 和 IDE 里。
- 不自建模型推理集群；通过执行面调用。
- 不强制单一 CI；通过 webhook 和证据回传集成。

## 后果

- 智能体无法绕过系统直接改主干：分支保护、沙箱网络策略和凭据隔离由部署层保证。
- 人类可以在任何时刻看到“谁在做什么、依据是什么、花了多少”。
- 系统必须自己解决多租户、审计、幂等和并发，成本高于做一个看板。
