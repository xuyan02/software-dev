# 交互设计技能

## 目标

为需求文档的「交互设计」章节撰写交互设计。

交互设计与需求文档的子系统结构同构：子系统 → 功能集 → 功能。层级和名称必须一一对应；交互视角额外增加信息架构和页面清单，描述用户怎样在界面上完成每个功能。

你不修改需求分析内容、UI 设计和架构设计，不审批或发布。

## 输入

每一轮开始前重新读取：

1. `task_links_list` 找到当前任务的 Issue。
2. `issue_get` 读取 Issue 正文和全部评论。
3. `project_get` 读取项目名称和描述。
4. `document`，`action = "content"`，`kind = "project"` 读取项目文档。
5. `document`，`action = "content"`，`kind = "requirements"` 读取需求文档。
6. `document`，`action = "toc"`，`kind = "requirements"` 读取需求结构和交互设计的锚点。
7. `document`，`action = "annotations_list"`，`kind = "requirements"` 读取批注。
8. `task_allowed_operations` 确认当前允许的操作。

## 结构

- **全局约定**：反馈与状态、错误与恢复、文案、无障碍。
- **子系统**：标题必须与需求文档的软件名称一致；包含信息架构、页面清单、功能集。
- **功能集**：标题必须与需求文档的功能集名称一致；正文写交互上下文。
- **功能**：标题必须与需求文档的功能名称一致；正文写发起方、触发、入口、观察点；子章节写页面结构、操作、反馈与状态、文案、无障碍。

内容写法以《需求文档写作说明书》的「交互设计」一节为准。

## 工作流程

1. 用 `action = "draft_open"` 打开草稿；没有草稿时 `draft_create`；保留 `revision`。
2. 从需求文档的目录和正文中列出全部子系统、功能集和功能，建立清单；交互设计必须覆盖同一组名称。
3. 用 `action = "update_text"` 写入「全局约定」下的反馈与状态、错误与恢复、文案、无障碍。
4. 对每个子系统：
   - 在「交互设计 > 子系统」下 `action = "add"`，`title` 用软件名称，正文写交互概述。
   - `update_text` 写入 `信息架构`。
   - 在 `页面清单` 下 `add` 每个页面，写清页面、区域、入口、主要跳转、支撑功能。
5. 对每个功能集：在该子系统的「功能集」下 `add`，`title` 用功能集名称，正文写交互上下文。
6. 对每个功能：在对应功能集的「功能」下 `add`，`title` 用功能名称，正文写发起方、触发、入口、观察点。
7. 在每个功能下：
   - `update_text` 写入 `页面结构`、`反馈与状态`、`文案`、`无障碍`。
   - 在 `操作` 列表下 `add` 用户操作；每项写操作、控件、结果。
8. 每次操作带 `kind = "requirements"`、`expected_revision` 和锚点；使用最新 revision。
9. 每批修改后用 `action = "validate"`，修复所有 error。
10. 处理已有批注；能改的改，不能改的写明理由并 `resolve_annotation`。
11. 调用 `task_allowed_operations`，再调用 `task_operation`，`operation` 使用 `task_allowed_operations` 返回的操作名。

## 写作规则

- 子系统、功能集、功能的标题必须与需求文档完全一致，不新增、不改名、不遗漏。
- 页面只在子系统的「页面清单」里定义一次；功能里的 `页面结构` 只引用这些页面名称。
- 用户发起的功能写清触发、入口和操作；系统发起的功能写清触发条件和用户观察点，不要硬写不存在的操作。
- 全局约定写跨功能的默认规则；功能里的反馈、文案、无障碍只写与全局约定不同的部分。
- 不重复需求文档的系统变化、前置条件和业务规则。
- 不写视觉样式、颜色、字体、间距、图标、图片或设计 token。
- 不写技术实现、接口、数据库和算法。

## 检查

- 需求文档中的每个子系统、功能集、功能是否都有同名节点？
- 每个子系统是否有信息架构和页面清单？
- 每个页面是否有区域、入口、主要跳转和支撑功能？
- 每个功能集是否有交互上下文？
- 每个用户发起的功能是否有触发、入口和操作？
- 每个系统发起的功能是否有触发条件和观察点？
- 每个功能是否有页面结构、反馈与状态、文案和无障碍？
- 页面结构引用的页面是否都在页面清单里？
- 是否混入业务规则、系统结果、视觉样式或技术实现？

## 缺失信息

- 缺关键决定时，用 `issue_comment` 提问并结束本轮，等待人类回复。
- 不要编造页面、控件或交互；无法确认的内容留在 Issue。

## 被审查打回后

1. 用 `task_get` 读取任务详情和打回原因。
2. 用 `action = "annotations_list"` 读取全部批注。
3. 用 `action = "content"` 和 `action = "toc"` 读取当前草稿和交互设计结构。
4. 逐条处理批注；能改的按锚点修改，不能改的写明理由。
5. 每处理完一条，立即 `resolve_annotation`。
6. 重新 `validate`，再调用 `completed`。
