# UI 设计审查技能

## 目标

审查需求文档的「UI设计」章节是否完整、清晰，并与交互设计的子系统、页面和状态一致。

UI 设计必须使用与交互设计相同的子系统和页面清单；每个页面要有布局、信息层级、组件、状态和设计稿图片。

只审查，不修改文档，不审批或发布。

## 审查前必须读取

1. `task_links_list` 找到当前任务的 Issue。
2. `issue_get` 读取 Issue 正文和全部评论。
3. `project_get` 读取项目名称和描述。
4. `document`，`action = "content"`，`kind = "project"` 读取项目文档。
5. `document`，`action = "content"`，`kind = "requirements"` 读取需求文档、交互设计和 UI 设计。
6. `document`，`action = "toc"`，`kind = "requirements"` 读取交互设计的子系统、页面清单和 UI 设计锚点。
7. `document`，`action = "annotations_list"`，`kind = "requirements"` 读取已有批注。
8. `task_allowed_operations` 确认当前允许的操作。

内容规则以《需求文档写作说明书》的「UI设计」一节为准。

## 审查方法

先建立覆盖矩阵：

```text
交互设计：子系统 → 页面清单
UI设计：  子系统 → 页面
```

逐层对照名称，再检查每个页面的内容。

### 1. 覆盖与名称

- 交互设计中的每个子系统是否都有同名 UI 子系统？
- 每个页面清单中的页面是否都有同名 UI 页面？
- 是否有 UI 页面在交互设计的页面清单里找不到来源？
- 名称是否完全一致，没有改写、合并或拆分？

### 2. 全局视觉规范

- 是否写清色彩、字体与排版、间距与圆角、图标与图片、动效、布局栅格与响应式？
- 是否具体到能指导实现，而不是“简洁”“现代”这类判断？
- 子系统是否只写视觉差异，没有重复全局规范？

### 3. 子系统与组件

- 子系统的视觉差异是否与全局规范矛盾？
- 组件规范是否覆盖跨页面复用的组件？
- 每个组件是否写清用途、结构、状态和规格？
- 页面里的组件引用是否都能在组件规范中找到？

### 4. 页面

- 关联功能是否都能在交互设计里找到？是否覆盖页面支撑的全部功能？
- 布局是否说明区域划分和操作区位置？
- 信息层级是否说明视觉优先级和信息组织？
- 组件列表是否写清组件、位置和状态？
- 状态列表是否覆盖默认、加载、空、错误和成功？
- 设计稿是否至少覆盖默认状态？是否有状态、图片和说明？
- 图片引用是否有 alt 文本，是否像真实资产引用而不是占位文本？

### 5. 一致性

- UI 设计与交互设计的页面、控件和状态是否矛盾？
- 是否引入了交互设计中没有的新页面、新组件或新状态？
- 是否混入用户操作步骤、页面跳转、控件行为、业务规则或技术实现？
- 是否重复全局视觉规范或组件规范里已经写过的内容？
- 布局和组件是否足以支撑交互设计中的操作？

## 逻辑推演

### 页面推演

对每个页面问：

- 默认态有设计稿吗？
- 加载、空、错误、成功状态有界面表现吗？
- 从交互设计进入这个页面后，用户能完成页面支撑的功能吗？
- 页面上的组件是否覆盖交互设计里的控件？

### 一致性推演

- 页面名称、组件名称和状态名称是否前后一致？
- 视觉层级是否与信息层级一致？
- 是否出现同一组件在不同页面规格不同的情况？

## 输出

用 `document`，`action = "annotate"`，`kind = "requirements"`：

- `anchor`：toc 中问题所在的 UI 设计锚点。
- `quote`：引用原文。
- `body`：具体缺陷、规则依据、修改建议和通过条件。

只写必须修改的问题；只要写了标注，就必须拒绝。每条标注必须能写清通过条件。已解决或不影响结论的问题不重复报。

提交结论：

- 只要写了标注，就调用 `task_allowed_operations`，再调用 `task_operation`，`operation` 使用 `task_allowed_operations` 返回的 `rejected` 操作名。
- 一条标注都没写时，才调用 `task_operation`，`operation` 使用 `task_allowed_operations` 返回的 `approved` 操作名。

## 不要做的事

- 不修改文档。
- 不审查需求分析内容或交互设计。
- 不写建议性、非阻塞标注。
- 不在写了标注后仍然通过。
- 不审批、不发布。
