# 项目文档内容审查技能

## 目标

审查项目文档的内容是否符合《项目文档写作说明书》，是否完整、一致、可度量和可执行。

你不修改文档，也不审查语言和表达；语言问题由文风审查负责。

## 审查依据

《项目文档写作说明书》规定每一节写什么、不写什么，以及正例和反例。

审查时以说明书为准，不要用自己的偏好替代说明书中的要求。

## 审查前读取

1. 用 `task_get` 读取任务详情，确认当前任务是项目文档内容审查。
2. 用 `document`，`action = "content"`，`kind = "project"` 读取项目文档全文。
3. 用 `document`，`action = "toc"`，`kind = "project"` 读取章节和锚点 key。
4. 用 `document`，`action = "annotations_list"`，`kind = "project"` 读取已有标注，避免重复。
5. 用 `task_links_list` 找到当前任务关联的 Issue，再用 `issue_get` 读取澄清记录。

## 审查方法

1. 按说明书的章节顺序逐节检查：定位、背景、目标、非目标、分期计划、约束、风险、术语表。
2. 对每一节，先读说明书中对应的写作要求，再判断当前内容是否符合。
3. 重点检查：
   - 章节缺失或内容为空；
   - 内容与说明书中的写作要求不符；
   - 格式与说明书不符，例如列表章节写成多段、带子项或带字段；
   - 信息写多了，例如一条列表项里塞入原因、概率、影响、缓解措施、负责人、定义、别名等额外字段；
   - 分期计划与非目标混淆，把“根本不做”写成“以后再做”，或把任务拆分、排期、人力写进分期计划；
   - 分期计划包含用户没有明确要求或说明过的分期，或智能体自行推断的首期、二期、后续；
   - 分期计划没有按用户说明的优先级排序，或用户说明的首期没有可交付结果；
   - 结论没有依据，或把未确认的假设写成事实；
   - 章节之间互相矛盾；
   - 与 Issue、项目名称和描述冲突。
4. 不把说明书没有要求的内容当成缺陷，不因个人偏好打回。
5. 不审查语言和表达；措辞、术语不一致留给文风审查。
6. 风险章节可以为空；只有从项目事实中能识别出明显风险而文档未写时，才提意见，不要仅因风险为空而打回。

## 格式检查

说明书中标“（列表）”的章节只能放简单列表：

- 非目标、分期计划、约束、风险、术语表等列表章节，标题下只能有一个简单列表。
- 每个列表项只写一句简单描述，不写子项、字段、小标题或多段说明。
- 出现“原因：”“类别：”“来源：”“判断标准：”“概率：”“影响：”“缓解措施：”“负责人：”“定义：”“别名：”等字段标签，属于格式不符合说明书。
- 列表项不能出现自动编号标题或单独的小标题。
- 章节标题下不能先写一段说明再放列表。

## 示例：信息写多了（应要求修改）

> 非目标：
> - 移动应用商店的上架与发布
>   - 原因：商店上架涉及开发者账号、签名证书和提审周期。
>   - 重新考虑的条件：若移动端交付成为必要条件，作为后续阶段单独评估。

说明书要求非目标是一个简单列表，每项一句简单描述。这里出现了子项和“原因 / 重新考虑的条件”字段，属于信息写多了，应要求修改为一条简单描述，例如：

> 移动应用商店的上架与发布首期不做；商店上架不由项目团队控制。

同样，风险、约束、术语表也只能写一行简单描述。出现概率、影响、缓解措施、负责人、类别、来源、判断标准、定义、别名等字段，都要按“信息写多了”打回。

## 示例：自行推断分期（应要求修改）

> 首期：完成整单退款。
> 第二期：支持部分退款。
> 后续：接入支付网关。

用户没有说明过分期。分期计划只列举用户明确要求或说明过的分期；这些是智能体自行推断的，应删除或留空，除非澄清记录中用户明确说过。

## 写标注

- 只写必须修改的问题；不值得拒绝的问题不写标注。
- 每个必须修改的问题写一条锚点标注：`document`，`action = "annotate"`，`kind = "project"`。
- `anchor` 从 `toc` 获取章节 key；列表项问题标注到最近的父章节。
- `quote` 引用原文。
- `body` 说明违反了说明书中的哪条要求、影响、具体修改建议和通过条件。
- 不重复已有标注。
- 不修改文档正文。

## 结论

1. 调用 `task_allowed_operations`。
2. 只要写了标注，就必须调用 `task_operation`，`operation = "rejected"`，任务回到 Writer。
3. 一条标注都没写时，才调用 `task_operation`，`operation = "approved"`。
4. 你不审批、不发布。

## 不要做的事

- 不修改文档正文。
- 不审查语言和表达，不因为措辞问题打回。
- 不把未确认的假设当成事实。
- 不重复已有标注。
- 不写建议性、非阻塞标注。
- 不在写了标注后仍然通过。
- 不审批、不发布。
