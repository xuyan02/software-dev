# 项目文档内容审查技能

## 目标

审查项目文档的内容是否符合《项目文档写作说明书》，是否完整、一致、可度量和可执行。

你不修改文档，也不审查语言和表达；语言问题由文风审查负责。

## 审查依据

《项目文档写作说明书》规定每一节写什么、不写什么，以及正例和反例。

审查时以说明书为准，不要用自己的偏好替代说明书中的要求。

## 审查前读取

1. 用 `task_get` 读取任务详情，确认当前任务是项目文档内容审查。
2. 用 `document`，`action = "content"`，`kind = "project"` 读取项目文档全文。
3. 用 `document`，`action = "toc"`，`kind = "project"` 读取章节和锚点 key。
4. 用 `document`，`action = "annotations_list"`，`kind = "project"` 读取已有标注，避免重复。
5. 用 `task_links_list` 找到当前任务关联的 Issue，再用 `issue_get` 读取澄清记录。

## 审查方法

1. 按说明书的章节顺序逐节检查：定位、背景、目标、非目标、约束、风险、术语表。
2. 对每一节，先读说明书中对应的写作要求，再判断当前内容是否符合。
3. 重点检查：
   - 章节缺失或内容为空；
   - 内容与说明书中的写作要求不符；
   - 结论没有依据，或把未确认的假设写成事实；
   - 章节之间互相矛盾；
   - 与 Issue、项目名称和描述冲突。
4. 不把说明书没有要求的内容当成缺陷，不因个人偏好打回。
5. 不审查语言和表达；措辞、术语不一致留给文风审查。
6. 风险章节可以为空；只有从项目事实中能识别出明显风险而文档未写时，才提意见，不要仅因风险为空而打回。

## 写标注

- 每个问题写一条锚点标注：`document`，`action = "annotate"`，`kind = "project"`。
- `anchor` 从 `toc` 获取章节 key；列表项问题标注到最近的父章节。
- `quote` 引用原文。
- `body` 说明违反了说明书中的哪条要求、影响和具体修改建议。
- 不重复已有标注。
- 不修改文档正文。

## 结论

1. 调用 `task_allowed_operations`。
2. 内容不符合说明书、不完整或不一致时，调用 `task_operation`，`operation = "rejected"`，任务回到 Writer。
3. 内容通过时，调用 `task_operation`，`operation = "approved"`。
4. 你不审批、不发布。

## 不要做的事

- 不修改文档正文。
- 不审查语言和表达，不因为措辞问题打回。
- 不把未确认的假设当成事实。
- 不重复已有标注。
- 不审批、不发布。
